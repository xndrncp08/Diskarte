# Live voice activity and Web Push delivery — 2026-10-15

This release implements the requested live Tambayan voice preview and the server-delivered Web Push infrastructure. It does not claim completion of the earlier full-platform master prompt. AI functionality remains excluded.

## Implemented

- Real, permission-filtered LiveKit room/participant snapshots on server-icon hover or Right Arrow; mobile long-press opens a bottom sheet through the existing context menu.
- Current member counts, eight participant avatars, overflow, microphone/screenshare indicators, streamer names, advisory speaking/deafen state and the existing profile card. Channel selection opens the existing voice view; hover never joins a call.
- Existing ref-counted Supabase presence supplies invalidation, avoiding permanent subscriptions to every server. The signed LiveKit webhook adds disconnect/track invalidations when configured. A room-summary count of zero cannot hide live participants. Navigation cancels pending hover previews; dismissal restores focus.
- Durable private-schema push outbox and per-device deliveries, session-bound subscriptions, ownership/MFA validation, current authorization checks, leased multi-worker claims, retries, deduplication, redacted attempt logs, expired endpoint cleanup and event reminders.
- Event capture for DMs/group DMs, mentions/role mentions, replies/threads, friend requests, invitation DMs, calls, moderation warnings and account suspension changes. Existing invitation DMs remain usable before the additive migration is applied.
- iOS installation guidance, explicit permission requests, device management, server-queued tests, synchronized event preferences/mutes, quiet hours/DND, opt-in lock-screen previews and sound preferences.
- Push, notification actions, safe deep links, account cleanup and persistent deduplication in the existing service worker. No second service worker, active-page polling requirement or paid provider dependency was added.
- Dialog dismissal now releases inert background state and restores focus at the start of exit. Next.js/ESLint config moved to 16.4.1, Sharp to 0.35.5 and source-map-js to 1.2.2.

## Architecture and limits

The authenticated preview route queries only RLS-visible channel room names, rechecks visibility after upstream work, and returns no LiveKit credentials. Participant snapshots are authoritative; client speaking/deafen signals are advisory and cannot introduce identities outside that snapshot. See [voice deployment](docs/voice-preview.md).

Push uses database triggers → a transactional outbox → an asynchronous pg_net wake → the protected Next.js dispatcher → a standards-based encrypted VAPID request. A named minute cron recovers retries/missed wakes and creates due RSVP reminders. Idle queues do not generate HTTP keepalives. Network-extension/Vault setup is separate from the additive portable migration and must be reviewed/applied by an operator. See [push setup, security, rollback and device acceptance](docs/web-push.md).

Resource bounds are tested: a 250-person room returns eight avatars; room detail requests run four at a time, up to thirty existing rooms per preview. Push claims twenty jobs per batch, sends four concurrently and bounds provider/database timeouts. No measured production latency, throughput or battery improvement is claimed; no production credentials or physical hardware were available for those measurements.
