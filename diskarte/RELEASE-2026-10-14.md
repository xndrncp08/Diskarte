## Implemented

- Message retries retain their original UUID; concurrent retry taps are deduplicated. Offline queues are scoped to the account, preserve uploaded attachment metadata and reject a full queue instead of evicting unsent messages. Backoff and online/visibility recovery are cleaned up on unmount.
- Optimistic edit/delete rollback preserves concurrent incoming messages. Reconnecting channel and DM conversations refresh known rows and fetch missed messages with forward keyset pagination. A recovery error offers Retry sync.
- Call joining uses a generation guard: leaving while a token loads, switching to another room and stale connection attempts cannot reopen an abandoned room. Tokens time out, failed SDK loads can retry, and restoring a muted call does not briefly enable the microphone.
- Mobile bottom navigation opens working Home, Messages, Explore and Profile destinations. The viewport follows visualViewport keyboard changes, honors safe areas and leaves pinch zoom available. The drawer manages focus and closes on Escape/back. Calls retain a mobile control strip while navigating. Messages support swipe-to-reply alongside existing keyboard and long-press menus.
- DMs now use the existing virtualized message list. Conversations retain a bounded, per-account reading position in this tab and expose a jump-to-latest control. Read marks are held while reading older messages or historical context.
- Desktop columns remain the default. Wide-screen floating navigation/chat panels support pointer and keyboard dragging/resizing, snapping to a position grid, stacking, reset and browser-local restoration; restored rectangles are constrained to the available workspace. Ctrl/⌘ K opens a lazy navigation palette; Ctrl/⌘ Shift H/M navigates home/messages.
- Explore searches explicitly listed communities by name/description/category, shows aggregate activity and membership counts, and joins public communities through existing ban and membership-limit rules. Admin settings expose listing/category controls.
- Global search retrieves permitted channel messages, threads and DMs with sender, community, date and media filters. Timestamp plus UUID cursors prevent skips at equal timestamps. Results open a permission-checked historical excerpt without creating gaps in the live history.
- Event and RSVP visibility now follows private voice-channel permissions. A regression test reproduced the original leak before the policy change.
- Shared workspace notes, task boards and focus timers are integrated into community navigation. Channel visibility, read-only/verification rules, account bans, MFA and timeouts constrain access. Atomic revisions detect concurrent edits, while clean editors receive live updates. Timers use the database clock. Creating/deleting items writes existing audit logs.
- PWA manifest shortcuts, service-worker registration, install guidance, update controls, bounded static caching and a tested offline page. Authenticated HTML, API responses and private media never enter the service-worker cache. Offline messages replay when their conversation is opened online; this is not a background delivery guarantee.
- Account/channel/thread-scoped text drafts persist in this browser and clear on sign-out, enforced session loss and deletion. Upload failures can retry; removed or abandoned uploads are cleaned up after completion. Failed uploads block sending rather than being silently omitted.
- Quiet hours, temporary notification pauses and expiring server mutes affect message sounds/rings and desktop alerts. Reduced transparency and increased contrast settings apply to app surfaces.
- Structured Next.js request error logs omit exception messages, actual URLs, headers and tokens. A bounded session-only diagnostic log records connection, call quality, message recovery/failure and client error metadata; Advanced settings expose connection checks and cache controls.

## Architecture and data changes

The app remains one Next.js 16 application using the existing Supabase and LiveKit infrastructure. No new runtime dependencies or paid services were introduced. New app modules stay inside `diskarte/`, preserving the Render build context.

New migrations, applied in filename order:

1. `20261013190000_server_discovery.sql`: additive listing/category columns, discovery and public-join RPCs.
2. `20261014000000_event_privacy_global_search.sql`: stricter event/RSVP policies; RLS-invoker global search; DM full-text and community activity indexes.
3. `20261014010000_shared_workspace.sql`: channel-scoped documents, edit-authority helper, transactional save/delete RPCs, revision checks, bounded payload validation, Realtime publication and audit target support.

The shared workspace table permits client SELECT only; mutations go through checked RPCs. Private notes/boards never enter public discovery or the offline page cache. Existing schema/data remain compatible with the previous app, although new features require these migrations.

## Deployment boundaries and incomplete scope

Docker is unavailable locally, so the throwaway Supabase/LiveKit stack, Docker image checks and authenticated multi-user browser journeys could not run on this machine. GitHub CI subsequently provided that stack and passed those checks. No production database URL/password or Supabase management token is configured. Production migrations were not applied; backup/restoration and live deployment were not performed. A Git push may trigger the repository's existing hosting automation; that is not a verified deployment result.

Physical iPhone/Android keyboard, background calling, foldable behavior, real network throttling, hardware permissions and LiveKit reconnection quality remain unverified. Existing authenticated mobile and multi-user journeys passed in CI; newly added navigation destinations and shared workspace editing have component coverage and still need dedicated browser/device workflows.

The following requested capabilities were not fully implemented in this execution. Most require further product/backend work, not missing credentials:

- Bot/developer applications, scoped credentials, webhooks, OAuth installations, slash commands and app review/discovery.
- No-code community automation, execution history and safe workflow testing.
- Opt-in AI provider boundaries, summaries, assistants and cost/consent controls; no AI service is claimed.
- Scheduled-message execution, translation, image cropping, custom sticker administration, full DM attachments, cross-device drafts and preference synchronization.
- Dedicated user/event/attachment discovery indexes, saved search/history, recommendations, approval questionnaires, verification/onboarding templates, ownership transfer and community export.
- Recurring/capacity-limited events, reminders and attendance tracking.
- Collaborative whiteboards, resource collections, shared layouts/presets, dedicated study goals/session summaries and authorized shared listening.
- New gamification/XP/achievement/reward systems, ban appeals, raid detection and moderation escalation workflows.
- Complete light/system themes, language/localization infrastructure and every newly requested settings category. Existing account, MFA/session, privacy/profile, notification and voice settings were preserved and partially extended.
- Background Web Push delivery and notification actions require a delivery backend and VAPID configuration; the app explicitly reports that they are not enabled.

Reading-position restoration currently saves offsets for the loaded history. Returning to a position outside the initial page requires loading older messages; full anchor-based history restoration is not implemented. Reaction reconciliation after a long disconnected interval is not covered by the new message-history recovery helper. Shared workspace revision conflicts preserve edits while the editor remains open; unsaved shared document changes are not synchronized drafts.
